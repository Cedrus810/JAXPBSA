# JAXPBSA 投稿 JCIM 审查（2026-10-02）

范围：审查当前源代码、README、RESULTS 最新修正、JCP26 存档与 JCIM 官方资料；没有投稿稿件，不能评价论文写作，也没有重新运行 GPU 性能基准。以下区分已有证据、代码问题与建议补充的实验。

判断：方向符合 JCIM，在线 OpenMM MM/PBSA 有明确的软件贡献；现有材料尚不足以支撑“普遍准确且优于现有 GPU PB 求解器”的主张。以在线分析软件为核心的 Application Note 比全面的通用 PB 方法论文更适合当前证据规模。这是投稿定位建议，不是录用预测。

## 1. 精度应以最终能量的绝对误差为主

- README 的 S4 对照：PB 为 780.52 vs 784.85 kcal/mol，差约 4.33；最终 MM/PBSA 为 −96.75 vs −92.45，差 4.30。PB 的 0.55% 不能表达最终能量误差。
- RESULTS §18.8 的 1YCR 当前默认：PB 为 292.656 vs 284.254，差 −8.402 kcal/mol。其余项误差很小，因此最终能量偏差也约 −8.4；相对于 Amber 的 −46.876，约为 18%。这是由已有分项推算，未重跑完整对照。
- “C/R 离散误差完全抵消、全部误差在配体”已经在 §18.8 被否定；h=0.5 下是否成立尚未测，但 README 仍使用这个表述。

建议：同一输入、同一模型下，分别改变 C/R 和 L 网格，报告逐帧配对误差、MAE/RMSE、最大误差、均值偏差及误差区间；加入平移相位与刚体旋转敏感性。Amber 的某个默认网格也不是连续解的真值，要区分求解器误差、离散误差和模型差异。

## 2. 25 蛋白结果含参数校准，不能全当独立验证

RESULTS §18.21 明确记录：通过同组蛋白的参考能量反推 gap_sigma=1.0，随后报告匹配程度。因此，这是参数校准后对照，不能据此独立确认原文使用的 σ，也不能证明对新体系的准确性。

完整 25 个蛋白中位绝对相对差 2.1%，平均绝对差 33.7 kcal/mol；排除 1TQG/2H5C/2IDQ 后，22 个中位差 1.7%。三个离群的比例约 1.43/1.15/1.17，制备差异尚未证实。主结果应保留全体，子集作为诊断，并公开排除理由。原子数一致不能保证电荷、质子化态、氢坐标或半径一致。

建议：取得参考输入并共用 PQR/电荷/半径；固定参数后使用独立蛋白验证。若无法取得，明确把 JCP26 对照定位为跨制备流程的复现尝试，保留不确定性。

## 3. 创新主张要面对现有 GPU 工具

pyDelPhi 已在 JCIM 报告 GPU PB、矩形盒、混合精度及多类介电模型验证；AmberTools 也已有 pbsa.cuda。仅“JAX 实现 + GPU 加速”不足以形成强的创新主张。

值得聚焦的贡献是：OpenMM 同卡在线完整 MM/PBSA、固定网格与 pilot 定尺、逐帧失效标记，以及在误差受控条件下的延迟和 MD 开销。

建议：增加至少一个可获得的现有 GPU PB 实现对照；CPU Amber 保留作为实践基线。若不可比较，解释输入/模型/软件限制，并收窄优越性主张。分别报告单 species PB、完整分析与 MD+分析；同时列编译成本、稳态延迟、吞吐、显存和误差。RESULTS §13 已显示旧配置下 40 核 Amber 吞吐略高于 2080 Ti，17.9× 仅属指定单帧延迟基线，不能泛化。

## 4. 主应用的覆盖范围仍窄

完整 MM/PBSA 外部对照主要是 S4 与 1YCR，均为蛋白–肽；25 个单体蛋白的溶剂化能不能替代结合能验证。

建议先扩展到几类独立复合物：中性与带电小分子配体、不同尺寸和净电荷、可适用时的蛋白–蛋白体系。具体数量随论文主张确定，不存在“达到某个数量就合格”的保证。软件一致性比较可使用同一批固定帧；若主张 MD 采样收敛、亲和力预测或生物学机制，则需独立重复、相关性修正和更充分采样。

没有熵项应明确标为 MM/PBSA 能量估计。若主张预测亲和力，应另有实验数据对照；不能只用与 Amber 一致来证明实验准确性。

## 5. 软件与数值契约存在具体缺口

1. `scripts/validate_mmpbsa.py` 的 `ours()` 直接把每帧 `delta_g_pb` 纳入均值，没有检查 `converged`、`margin_A` 或 `margin_lig_A`。因此验证路径可能把失败帧计入结果；这是需优先修复的验收漏洞，不代表存量结果已被证实错误。
2. README 和包文档概括为“fp32 arrays, fp64 reductions”，但 `pb/solver.py` 的 b_norm 与 CG dot 都没有指定 fp64 累积，fp32 输入下这些归约仍是 fp32。要么改准确描述为“能量归约 fp64”，要么改实现并重新验证性能与收敛。
3. NLPB 暴露 `temperature_K`，但温度仅用于 Debye κ²；源项、边界与能量使用 298.15 K 的固定 BJERRUM_VAC/KT_TO_KCAL，非线性项直接用 sinh(u)。线性方程可在固定参考温度的势单位下成立，但 NLPB 在其他温度下需同步调整无量纲势或 sinh 的参数。这是静态推导发现，未做跨温度数值验证；可先限制 NLPB 为 298.15 K。
4. `surface="fraction"` 在 RESULTS §18.14 的 1YCR 完整路径有 OOM，未见后续解决记录；高斯模型也不能凭数值收敛就主张适合当前结合能用途。功能列表需标明各模型的验证范围。
5. 跨 GPU 的逐位一致是已测配置的观察，不宜保证所有体系、JAX/CUDA 版本均如此。

## 6. 可复现交付尚未完成

README 明示研究代码与后续 CI；pyproject 没有固定复现实验环境，测试依赖还使用了未列入 test extra 的 PDBFixer。当前本地出现 JAX CUDA plugin 0.11.1 与 jaxlib 0.10.2 不兼容警告。data/ 被忽略，JCP26 的 archive/ 目前也未跟踪；本地有完整文件不等于外部审稿人能取得。

建议：发布固定版本和环境说明，提供匿名可访问的代码、输入、参考输出、轨迹与复现命令，长期存档并给出持久标识。CI 至少跑小型 CPU 正确性检查，GPU 测量单独保存硬件和软件版本。将 RESULTS 中作废数字移到历史记录，正文统一引用当前版本。
